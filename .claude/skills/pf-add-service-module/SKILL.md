# Add a service module (a third-party SDK behind a framework port)

Full recipe: **`docs/framework/recipes/add-service-module.md`**.

## 0. The gate before you write anything

| What you have | Where it goes |
|---|---|
| An **external-SDK implementation of a port that already exists** | This skill. |
| Logic with **no external dependency** | Just register it in the SKU installer. No module. |
| A **new port**, a **new `BootCap`**, or a dropped cap | **Spine change** — route it. |

Adding a module is **not** a spine change: no framework assembly, no framework reference edge, no
RenderLayer, no event type, no kernel boot node.

## 1. Which shape is your port?

| Port | Resolution | Your module |
|---|---|---|
| `IAnalyticsProvider` | `IEnumerable<IAnalyticsProvider>` | **Additive** — N coexist. |
| `IAdsService`, `IPurchaseService` | Single resolve | **Replacement** — supersedes the fake. |

Replacement works by **registering later**, never by deleting the framework's line: SKU installers run
after every framework installer, and in VContainer the later registration wins. The superseded fake
stays registered and is never constructed.

## 2. Layout

```
Assets/<Sku>/Integrations/<Sdk>/
├── Game.Integrations.<Sdk>.asmdef     defineConstraints: ["PF_<SDK>"]
├── I<Sdk>Bridge.cs / <Sdk>Bridge.cs   the SDK seam + thin shell
├── <Sdk><Port>.cs                     your implementation
└── <Sdk>Installer.cs                  ScriptableObject : IInstaller
```

`defineConstraints` is what makes it optional — an unsatisfied constraint means the assembly is **not
compiled at all**, so the files sit inert and a SKU without the SDK still builds green. Pair it with
`versionDefines` so the SDK's UPM package sets the define automatically.

Reference `ClassicSpins.PrototypeFramework.Application` (the port) — never `Infrastructure` or
`Composition`, except `VContainer` for the installer.

**SDK shipped as a `.unitypackage` with no asmdef?** It lands in `Assembly-CSharp`, which no asmdef
assembly can reference. Prefer the SDK's UPM build; else add an asmdef to the SDK folder (a vendored
edit an upgrade wipes); else drop your own asmdef and live in `Assembly-CSharp` behind `#if`.

## 3. Wire it — never edit `CreateInstallers()`

`RootLifetimeScope` carries a serialized `List<ScriptableObject>` filtered by `is IInstaller`. It is
type-erased on purpose: nothing needs a compile-time reference to your module.

```csharp
public void Install(IContainerBuilder builder)
    => builder.Register<FirebaseAnalyticsProvider>(Lifetime.Singleton).As<IAnalyticsProvider>();
```

Dropping the asset into the Master Scene slot is **human zone** (rule #12) — live editor, not YAML.

## 4. The shipped fake is the specification

Read the implementation you are replacing. Ports carry contracts the interface does not state:

- **`IAdsService`** — publish `AdVisibilityChanged` at show-start **and** show-end, the latter in a
  `finally`, or a failed show strands the audio duck, interaction lock, gameplay tick and banner
  reflow. Auto-log the outcome via `AdAnalyticsMapping` → `IAnalytics`.
- **`IAnalyticsProvider`** — never throw. `FanOutAnalytics` re-queues on a throwing provider, silently
  turning live telemetry into an ever-growing buffer.

## 5. Split the SDK boundary

Static native APIs (`MaxSdk.*`, `FirebaseAnalytics.*`) make a module untestable under the `dotnet
test` ship gate. Put the SDK behind a narrow interface you own; keep the state machine (load, show,
timeout, backoff, publish ordering, result mapping) on your testable side, and let the bridge be thin
enough to review by eye.

## 6. Async init → override, do not add

SDK init that must be awaited / can fail / needs ordering is tier 2. Replace, do not add:

```csharp
builder.RegisterInstance(BootNodeOverride.Replace("AdsInit", new MaxAdsInitNode(...)));
```

Keep `Id` and `Provides` identical — a cap that loses its sole provider makes `RunUntilAsync` /
`RerunFromAsync` complete silently without ever becoming ready. Keep `Required => false`.

## 7. No defaulted constructor parameters

VContainer ignores C# default values and resolves every parameter. `ILog log = null` is a hard
dependency wearing a disguise. Take the parameters and null-check.

## 8. Distribution

One SKU → stays in `Assets/<Sku>/Integrations/`. Two or more → its own UPM package depending on the
framework. **Never inside the framework package** — every SKU would inherit the SDK dependency, which
is the whole thing modules exist to prevent.

## If it breaks

| Symptom | Cause |
|---|---|
| The fake still runs | Installer asset not in the Master Scene slot, or the define constraint left the assembly uncompiled. |
| `type or namespace <Sdk> not found` | SDK has no asmdef — it is in `Assembly-CSharp`. |
| Input locked / audio ducked / sim frozen after an ad | Show-end `AdVisibilityChanged` missing on some exit path. |
| Events vanish, buffer grows | A throwing provider, or consent unresolved so the fan-out holds everything. |
| `VContainerException` on a parameter you thought optional | A defaulted constructor parameter. |
