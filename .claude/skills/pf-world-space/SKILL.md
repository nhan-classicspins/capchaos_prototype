# World space — the rig ruler

Full recipe: **`docs/framework/recipes/add-world-object.md`**. Full derivation:
**`docs/framework/architecture-map.md` §6**.

## The invariant

**`1 texture px == 1 canvas reference px == 1 world unit == 1 TMP font point`** — four links, all
required:

| Link | Written by |
|---|---|
| sprite import `Pixels Per Unit = 1` | `Assets/<Sku>/Editor/SpriteImportDefaults.cs`, on an asset's **first** import only (`Framework/Doctor` check 14). It hooks `OnPreprocessTexture`, so a **`.psd`/`.psb`** (`PSDImporter`, not `TextureImporter`) never reaches it and lands at PPU 100 **with no log**; same for art outside `Assets/<Sku>/`. Fix those in the Inspector |
| `Canvas.referencePixelsPerUnit = 1` | `WorldSpaceCanvasScaler` at runtime — the field is never serialized, so a canvas without that component loads at Unity's 100 |
| host canvas `localScale == 1` | `WorldSpaceCanvasScaler.Apply()` |
| `TMP_Text.isOrthographic == true` — TMP's font scale carries **no** multiplier | `TextMeshProUGUI.Awake()`, unconditionally, for every uGUI text. A **Renderer-drawn `TextMeshPro`** (3D text under `WorldRoot`) serializes it **`false`**, and TMP then multiplies font scale by `0.1` (`TMP_Text.cs`: `orthographicMultiplier = m_isOrthographic ? 1 : 0.1f`) — tick Orthographic Mode on that component |

A 200×200 px sprite is 200×200 world units and matches a 200×200 canvas `Image` exactly, and a
`fontSize` of 200 is 200 units of type — one ruler, no conversion anywhere. Type ratios and how to
measure them: `pf-visual-design`.

## The safe rect

Design rect **1080×1920, centred on the camera**, `screenMatchMode: Expand`. So
**`x ∈ [−540, 540]`, `y ∈ [−960, 960]` is visible on every device** — a device off 9:16 *adds* bleed
on one axis and never crops. Design inside the rect; treat the rest as bleed.

In code, **read it — never retype it**: inject `IWorldViewport` (Presentation, tier-1 root singleton).

| Member | Answers |
|---|---|
| `SafeRect` | that rect, as a world-space `Rect` centred on the GamePlay camera. Identical on every device **as long as the host is on `Expand`** — it is `min(visible, design)` per axis, so a host left on the component's serialized `MatchWidthOrHeight` default narrows to what is genuinely on screen instead of over-promising |
| `HalfWidth` / `HalfHeight` | this device's **actual** half-extent from the camera centre (540/960 at 9:16, 540/**1200** at 9:20, **720**/960 at 3:4) — for bleed, off-screen spawns, clamping to the real edge. Half-**extents**, not coordinates: a world x is `SafeRect.center.x ± HalfWidth` |

Every property recomputes off the live camera per read: **safe to read every frame, never safe to
cache.** A field holding `HalfHeight` across frames is the hardcoded `960` bug one hop away.

## `orthographicSize` is not a constant

`Apply()` writes `cam.orthographicSize = logicalResolution.y / 2` **before** it measures the frustum,
which is what makes `localScale` come out exactly 1 in the same pass:

| Viewport | `orthographicSize` | Visible world units |
|---|---|---|
| 1080×1920 (9:16) | **960** | 1080 × 1920 |
| 1080×2400 (9:20) | **1200** | 1080 × 2400 |
| 1536×2048 (3:4) | **960** | **1440** × 1920 |

Rig YAML always reads `960` because a `sceneSaving` hook stamps the canonical reference-aspect
values. That is a **save artefact, not a runtime value** — never hardcode it, never derive a size or
a screen edge from it, and never read `Camera.orthographicSize`: `IWorldViewport.HalfHeight` is the
sanctioned reader of this projection (`HalfWidth` for the other axis). To zoom gameplay, scale a world
content root; the camera is the scaler's.

## Placement

```csharp
// worldRoot: no framework API exists — this scene-name lookup is the honest current answer.
var worldRoot = gameObject.scene.GetRootGameObjects().First(g => g.name == "WorldRoot").transform;
var go = Object.Instantiate(prefab, worldRoot, false);       // false ⇒ worldPositionStays: false
_layers.Stamp(go, RenderLayers.GamePlay, sortingOrder: 10);  // IRenderLayerRegistry
shadow.sortingOrder = 9;                                     // AFTER Stamp — it flattens the subtree
```

- **Two questions decide the parent, in order, and they are asked per object (rule #16).**
  *What does it anchor to?* — a screen edge or the safe area (HUD, score, top bar, currency pill)
  ⇒ the layer that owns it (`Ui` for screen furniture, `Popup` for dialog chrome, `Overlay` for
  system overlays), and if it is uGUI you are done at that layer's `GetHost`; a position in the
  game's own space ⇒ ask the second. *How does it draw?* — a `Renderer` (`SpriteRenderer`,
  particles, tilemap, mesh) goes under `WorldRoot`; a uGUI graphic (anything on a
  `RectTransform`/`CanvasRenderer`) renders only under a `Canvas`, so it goes under `GetHost(id)`
  **even when it is the gameplay view** — the shipped PingPong match is uGUI under
  `GetHost(RenderLayers.GamePlay)`. Both get `Stamp`ed. **Never answer once for a whole feature** —
  a board and the score above it take two answers. Recipes:
  `docs/framework/recipes/add-world-object.md` · `docs/framework/recipes/add-widget.md`.
- **A screen-anchored `Renderer`** (edge particle burst, full-bleed SpriteShape) cannot be uGUI:
  `Stamp` it onto the owning layer and parent it under that layer's host — riding the camera every
  frame is the point for screen-anchored content, not the bug.
- **Pointer input on world content is a layer declaration, not an authoring step.** A layer manifest
  entry takes an optional `physicsRaycast`: `"none"` | `"2d"` | `"3d"`, **case-sensitive**, omitted ⇒
  `none`, illegal value **fails codegen**. Codegen emits `RenderLayers.WorldRaycastOf(id)` →
  `WorldRaycastMode`; as the Root container is built, `WorldPointerRaycasterInitializer` hands the rig to
  `WorldPointerRaycasters.EnsureOn`, which `AddComponent`s uGUI's
  `Physics2DRaycaster`/`PhysicsRaycaster` onto that layer's **camera** (get-else-add, before the
  first scene loads). **Nothing is authored** — the component is in no serialized scene, so verify it
  with the one **boot smoke** §8a allows for a wiring change, never in the Inspector. It pins
  `eventMask` to the layer's own culling bit (the GamePlay camera may also mask `Default`, and
  `cullingMask & eventMask` would otherwise make every `Collider2D`
  on `Default` tappable) and `maxRayIntersections` above zero (uGUI's `0` allocates per pointer event);
  the types are reached by name, so `Runtime/link.xml` keeps IL2CPP from stripping them.
  **Only `GamePlay` declares it (`"2d"`) by default**: a raycasting camera pays a physics query per
  pointer event, so opt in per layer. Depth orders input **across** layers, not within one camera —
  world content and that layer's host-canvas UI fall through to sorting order, then hit distance.
  A mode on a **game** layer compiles but reaches nothing: the rig binds only the six framework layers. You still own the **collider** in the
  prefab and a View that implements `IPointer*` and **relays** — rule #10, convert to game units
  first (`pointerCurrentRaycast.worldPosition` is the hit point); rule #9, never poll. No `IPointer*`
  base class ships (it would put `UnityEngine.EventSystems` on a public framework surface). Priority
  is free: the EventSystem sorts camera raycasters by depth = render band, so `Popup`/`Overlay`
  blockers already beat `GamePlay`.
- `GetHost(RenderLayers.Ui)` returns the `SafeArea` child, so a widget gets the notch inset for
  free; it throws for a layer the rig never wired, because `RootLifetimeScope` omits an unwired
  binding.
- A `GetHost(id)` canvas is repositioned onto its camera every frame, which is why a `Renderer`
  parented there travels with the camera.
- Omitting the `false` picks the `worldPositionStays: true` overload, which rewrites `localScale`
  against a non-identity `WorldRoot` and breaks the "leave `localScale` at 1" rule.
- `Stamp` forces `localPosition.z = 0` and one uniform `sortingOrder` across the **whole** subtree.
  Express in-object layering with `sortingOrder`, never with z.
- z budget: canvas plane at `z = 0`, cameras at `z = −1000`, `near 0.3`/`far 2000` ⇒ usable
  `z ∈ [−999.7, +1000]`; outside that, content is **clipped**.

## Physics rides the same ruler

`PixelsPerMeter = 100`, so every length/velocity/acceleration setting is ×100 — gravity **−981**,
default contact offset **1**. A constant copied from a metre-scaled tutorial is 100× wrong.

## Screenshots: FHD, in the rig's own orientation

`screenshot-camera` defaults to **1920×1080 landscape** and swaps that onto the camera, so on a portrait
rig the scaler recomputes for 16:9 (~3400 units of visible width) and the capture is a picture of an
aspect the game never ships. Always pass the size explicitly: **FHD in the orientation this SKU's design
rect declares** — `width: 1080, height: 1920` on the shipped portrait rig, `1920×1080` if the rect is
landscape — or the device aspect under test. Read the orientation off
`WorldSpaceCanvasScaler.ReferenceResolution` (the host's `CanvasCameraFitter._referenceResolution`);
never assume it.

## If it breaks

| Symptom | Cause |
|---|---|
| A 100×100 px sprite is 1×1 unit | Imported at PPU 100 — predates `SpriteImportDefaults`, has a per-asset override, is a `.psd`/`.psb` (never seen by it, logs nothing), or sits outside `Assets/<Sku>/`. Fix it in the Inspector; never delete the `.meta` (it re-mints the GUID). |
| `SetNativeSize()` gives a 10000×10000 rect | `Canvas.referencePixelsPerUnit` is 100 — that canvas has no `WorldSpaceCanvasScaler`. |
| Text is 10× too small, or only "looks right" at a four-digit `fontSize` | A Renderer-drawn `TextMeshPro` with `isOrthographic == false` (TMP's ×0.1 font scale). Tick Orthographic Mode; scaling `fontSize` up to compensate leaves every metric off by 10×. On a uGUI text this cannot happen — a four-digit size there is simply 10× too big. |
| The object follows the camera | Parented under a `GetHost(...)` host canvas instead of `WorldRoot`. |
| Right at 9:16, wrong on a tall phone | A hardcoded `960`/`orthographicSize`, or a size derived from `Screen.*`. Use world units plus `IWorldViewport` — `SafeRect` for the guaranteed rect, `HalfWidth`/`HalfHeight` for this device's real extent. |
| Sub-object layering collapsed, or a z offset vanished | `Stamp` flattened both across the subtree. Re-apply `sortingOrder` after the call. |
| Un-`Stamp`ed content is invisible **or** visible-but-mis-ordered | **Rig-dependent** — read the `GamePlayCamera` culling mask. Own layer only ⇒ invisible. Also masking the built-in `Default` (permitted, not required) ⇒ it draws at the GamePlay band but keeps its prefab's SortingLayer, so ordering against `Stamp`ed siblings is wrong. Either way: check `gameObject.layer` and `Stamp`. |
| A capture looks nothing like the Game view | `screenshot-camera` ran at its landscape-FHD default. Re-capture at FHD in the rig's orientation (1080×1920 on the portrait rig). |
| Geometry is right but the screen still looks unfinished | Correct placement is not a finished surface — rule #17. Load `pf-visual-design`: ground, empty slots, spacing rhythm, type hierarchy. |
