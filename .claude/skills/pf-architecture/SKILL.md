# PrototypeFramework — architecture map

Full detail: **`docs/framework/architecture-map.md`**. Exhaustive type → assembly → file lookup:
**`docs/framework/framework-api.index.json`** (generated — use it instead of grepping).

## Assembly graph (namespace ≡ assembly name, always)

Dependencies point one way, inward. Six framework assemblies under
`Packages/com.classicspins.prototype-framework/Runtime/`, **eight** SKU assemblies under
`Assets/<Sku>/` — the SKU's five feature tiers mirror the framework's name for name, so nobody
translates between the halves.

| Assembly | Holds | References |
|---|---|---|
| **Domain** | Engine-free POCOs: models, rules, key types, event types, `IRandom` | **nothing** (`noEngineReferences`) |
| **Application** | Ports with no engine types in their signatures; policy POCOs; the boot scheduler | Domain |
| **Presentation** | Ports whose signatures carry engine types; `ScreenBase`, `DialogBase<T>` (plain classes, never MonoBehaviour) | Views, Application, Domain |
| **Views** | MonoBehaviour View bases, `TextProxy` | only UnityEngine, TMP, LitMotion |
| **Infrastructure** | Adapters + **every fake** | Presentation, Views, Application, Domain |
| **Composition** | Installers, `RootLifetimeScope`, `IScopeTracker` impl | Infrastructure, Presentation, Application, Domain |
| **Game.Domain** | The game's rules core: models, generators, pure logic | PF Domain (`noEngineReferences`) |
| **Game.Application** | The game's ports, screen `Param`s, policy POCOs | Game.Domain, Game.Gen, PF Application/Domain (`noEngineReferences`) |
| **Game.Presentation** | Controllers: screens, dialogs, widgets, presenters. **No container type** | Game.Application/Domain/Gen/Views + PF Presentation/Views/Application/Domain |
| **Game.Infrastructure** | The game's adapters and boot nodes | everything below + PF Infrastructure |
| **Game.Composition** | Installers, scopes, `<Sku>FrameworkSettings` | everything above + PF Composition, VContainer |
| **Game.Views** | Only the game's MonoBehaviour Views — **cannot see a service or controller** | `CS.PF.Views` |
| **Game.Gen** | Generated keys, engine-free | PF Domain (`noEngineReferences`) |
| **Game.Editor** | Editor-only SKU tooling | — (`includePlatforms: ["Editor"]`) |

`Domain` referencing nothing is what makes the headless `dotnet test` ship gate possible —
`Game.Domain` and `Game.Application` inherit it, which is why the SKU gate **globs** them
(`Assets/<Sku>/**/Domain/**/*.cs`) instead of hand-listing engine-free files.
`Views` exists as a separate leaf so `Game.Views` can inherit view bases *without* seeing services.
`Game.Gen` is engine-free only because `AssetKeys.gen.cs` — the one generated file binding a
`UnityEngine` type — lands in `Assets/<Sku>/Presentation/Gen/` instead.

**A new assembly or reference edge is a spine change** — route it, do not just add it.
`AssemblyGraphTests` pins the graph by set-equality (both a missing and an extra edge fail) and
reddens CI by name.

## Two axes: assembly = spine, folder = feature

The eight assemblies are not eight folders you file work into. **Anchors** hold the `.asmdef`s;
**feature folders** join them with a three-line `.asmref`:

```
Assets/<Sku>/
  Domain/ Application/ Presentation/ Infrastructure/ Composition/  ← .asmdef anchors
  Views/ Gen/ Editor/                                              ← the other three
  Features/Gameplay/Domain/         Game.Domain.asmref
  Features/Gameplay/Presentation/   Game.Presentation.asmref
  Features/Gameplay/Composition/    Game.Composition.asmref
```

Unity picks the **nearest ancestor** `.asmdef` or `.asmref`. So the compiler enforces the
architecture while a reviewer still reads one feature in one folder. `Features/<X>/` itself holds no
`.cs` and no `.asmref` — every script sits under exactly one declared layer.

You never hand-create these: `Framework/Setup Wizard` emits the eight `.asmdef`s, `Scaffold.Sync`
writes the `.asmref` beside the first stub it lands in a layer folder, and **Doctor check 15**
reports a missing anchor or a dangling `.asmref`. A script with no ancestor `.asmdef`/`.asmref`
compiles into `Assembly-CSharp` — green, and outside the AD-1 boundary entirely.

**An empty anchor is legitimate**: a SKU with no adapters still declares `Infrastructure/`, so its
first adapter is a file move rather than a routed spine change.

## Scope tree — the ownership axis

| Scope | Created by | Holds | Dies when |
|---|---|---|---|
| **Root** | `RootLifetimeScope` | Every framework service, the boot kernel, `IScopeTracker`, `PoolContext` | App exit |
| **Scene** | `SceneScopeFactory` → `SceneLifetimeScope` | The screen controller, its dialogs, its subscriptions | The screen unloads |
| **Gameplay** | `GameplayScopeInstaller` | The sim, `GameplayTickDriver`, per-match state | The match/branch ends |

Everything stateful belongs to exactly one scope and dies with it. Dispose order is mechanical law.

**Ctor injection is the only resolution path** — no service locator, no singleton, no
`FindObjectOfType`. A class's dependencies *are* its constructor signature.

`GameplayTickDriver` is the scope's **sole tick entry**; a Model advances by a fixed dt passed as a
parameter and never reads `Time.*`.

## Three-tier init law

> **Boot node ⟺ must be awaited, OR can fail meaningfully, OR needs external ordering.**

- None of the three → **tier 1**, plain DI construction.
- Feature startup → **tier 3**, `IAsyncStartable` in the feature's own child scope.
- Framework/app-wide and one of the three holds → **tier 2**, `IBootNode`.

A feature-init node in the kernel is a boundary violation: the kernel must not know features exist.

## Render layers

Framework: `UnderGamePlay` −10 · `GamePlay` 0 · `OverlayGamePlay` 5 · `Ui` 10 · `Popup` 20 ·
`Overlay` 30. Each owns one Unity culling layer (`PF` + id) that its camera masks **exclusively**.
SKU bands are derived from `framework.layers.json` — inside the base/ceiling, never on a framework
depth (today −9..−1 / 1..4 / 6..9 / 11..19 / 21..29), budget 6. A new layer needs **absolute ordering
vs a standard layer, OR its own camera config, OR bulk culling** — otherwise use `sortingOrder`
inside an existing layer.

> **Parenting is not placing.** `Instantiate(prefab, GetHost(id))` alone leaves the instance on its
> prefab's layer, which no camera masks — it is invisible. Always `Stamp(instance, id)` after.

The rig ships as a **URP camera stack**: `UnderGamePlayCamera` is the only Base camera (lowest depth, owns
the colour clear), the other five are Overlays in its stack in ascending-depth order, and each host canvas
is a child of its camera. **In a stack the stack order decides what draws on top — not the depth value.**

> Each WorldSpace render-layer host canvas needs its **own `GraphicRaycaster`**. Missing one =
> "the UI is not clickable", `RaycastAll` returns 0 hits.

## Config layering

Precedence **bundled default → remote override → local A/B**, merged per key. The untrusted remote
layer is validated per key; failures come back as `ConfigSkip` **data, never an exception**. The SKU
game installer owns the **single** `ConfigDefaults` registration — two is a VContainer conflict,
zero makes every `Get` return `0`.

## Where does this go?

| Adding… | Goes in | Recipe |
|---|---|---|
| A pure game rule / model | `Assets/<Sku>/Features/` as a POCO | cover it headlessly |
| A screen | `game.scenes.json` → `Scaffold.Sync` | `pf-add-screen` |
| A dialog / widget / toast | `Manifests/Scaffold/game.*.json` → `Scaffold.Sync` | `pf-add-dialog` |
| Screen furniture — a score/HUD readout, a timer, a top bar, a currency pill: anything anchored to a screen edge or the safe area | uGUI under the `GetHost` of the layer that owns it — `Ui` for screen furniture, `Popup` for dialog chrome, `Overlay` for system overlays. The anchoring question is asked **per object** (rule #16), so a score above a world-space board is still this row | `docs/framework/recipes/add-widget.md` · `pf-add-dialog` |
| Something anchored in the game's own space that draws through a **`Renderer`** (sprite, particles, tilemap) | the scene's `WorldRoot` + `Stamp` — a uGUI view, even a gameplay one, goes under `GetHost` instead | `pf-world-space` |
| A tunable number | `game.configkeys.json` + `ConfigDefaults` | `pf-add-key` |
| A user-visible string | the Master CSV | `pf-add-key` |
| Startup work | check the three-tier law first | `pf-add-boot-node` |
| An announcement of something that happened | `Events/game.events.json` + a broker registration | `pf-add-event` |
| Visual behaviour | `Assets/<Sku>/Views/` (layout via Unity-MCP) | `pf-framework-rules` |
| A new external SDK | a **port** + a **fake** beside it, adapter in Infrastructure | spine review if it adds an edge |

## v1 has no remote backend

No CDN, no ad network, no store, no analytics service — every outbound path runs on a **fake**, by
design. If a task needs a real backend, say so and route it rather than improvising one.
