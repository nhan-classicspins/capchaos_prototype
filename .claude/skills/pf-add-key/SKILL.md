# Add a typed key

Full recipes: **`docs/framework/recipes/add-config-key.md`** and
**`docs/framework/recipes/add-loc-key.md`**.

**Never hand-edit a `.gen.cs` file.** The manifests live **outside `Assets/`**, so editing one
raises no Unity import event — you must run codegen yourself.

## Config value — the step people forget

`game.configkeys.json`:

```json
{ "id": "ShopRefreshHours", "type": "float", "value": "shop.refreshHours", "order": 6 }
```

**Then register the default.** The framework registers **none** — the SKU game installer owns the
**single** `ConfigDefaults`:

```csharp
builder.RegisterInstance(new ConfigDefaults(new Dictionary<string, object>
{
    [GameConfigKeys.ShopRefreshHours.Value] = 6f,
}));
```

The value's runtime type declares the key's type for per-key validation of the remote layer.

| Mistake | Result |
|---|---|
| Two `ConfigDefaults` registrations | VContainer resolution conflict at boot |
| No registration | Every `Get` silently returns `0` |

Precedence: **bundled default → remote override → local A/B**. Bad remote values become `ConfigSkip`
data, never an exception.

## Localized string — rule #4 is absolute

`Assets/<Sku>/Content/Localization/loc.csv`:

```csv
key,en,vi
shop.refresh_in,"Refreshes in {0}h","Làm mới sau {0} giờ"
```

- Quote any value containing a comma — this is real RFC 4180 CSV.
- **Format args must match across every locale**, or `string.Format` throws at runtime.
- **Never parse CSV with `string.Split(',')`** (rule #3).
- v1 locales: `en`, `vi`.

**No string literal reaches `SetText` from game code** — everything goes through a `LocKey`. A View
never composes a sentence and never chooses which string to show.

## Gate

```sh
Tools/Build/pf-build.sh codegen --check    # exit 1 = a generated key is stale
Tools/Build/pf-build.sh validate           # duplicate keys/locales + cross-locale format-args
```

`validate` runs as CI step 2, **before** the Unity compile.
