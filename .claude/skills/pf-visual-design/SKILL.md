# Visual design — a surface ships finished

Verbatim rule: **`docs/framework/AGENTS.framework.md` §1 rule 17**. Origin and rationale: brief
**§8.7**. Geometry and the ruler this all sits on: the `pf-world-space` skill.

> **The human/machine zone boundary is about mechanism, not authority.** It says a prefab is edited
> through the live editor (raw YAML corrupts GUIDs). It never said the *look* is not yours to decide.

Rule 17 covers **shipping player-visible surfaces**. It is not retroactive: editing a legacy screen
does not oblige you to retrofit it, and editor-only or debug-only UI is out of scope.

## The authority ladder — stop at the first rung that answers

| Rung | Source | What it binds |
|---|---|---|
| 1 | **Artist spec** — `docs/art-direction.md` | Follow it. Any deviation is named in the spec's Design Notes, never silent. |
| 2 | **The SKU's existing design tokens** | A second feature must not invent a second palette. Existing tokens bind you like an artist spec would. |
| 3 | **You** | No spec, no tokens ⇒ decide, then **write the tokens down**. An undocumented choice is a rung-2 failure for the next feature. |

Only `docs/art-direction.md` and "one token file per SKU" come from the verbatim rule. The extra probe
paths (`docs/art/*.md`, `Assets/{sku}/Content/art-direction.md`) and the token path below are
**convention, not contract** — useful defaults, but a SKU that puts them elsewhere is not in breach.

**When rungs collide:**
- An artist spec that lands *after* tokens exist **supersedes** them — rewrite the token file in the
  same change, rather than leaving the palette split between two sources.
- Rung 2 missing a value the new feature needs ⇒ **extend the token file in that change**. Declaring
  a local literal "just this once" is the exact shape rule 17 rejects.

## The token file is code, not an asset

`Assets/{sku}/Views/DesignTokens.cs` — a `static class` in the SKU's `Game.Views` assembly. Resolve
`{sku}` from `framework.config.json`; one token file per SKU.

**Why code is the whole point.** A ScriptableObject is a `.asset`, so rule 12 routes every tweak
through the live editor: no loop, no diff, no refactor, and *changing* a colour costs what *authoring*
it cost. That is precisely why an ugly layout never gets a second pass. A static class is machine
zone — you write it, review diffs it, and re-scaling every gap is one edit.

```csharp
using UnityEngine;

namespace Game.Views
{
    /// <summary>The SKU's single source of visual truth. Views index it; nothing redeclares it.</summary>
    public static class DesignTokens
    {
        public static Color Hex(string rrggbb) =>
            ColorUtility.TryParseHtmlString("#" + rrggbb, out var c) ? c : Color.magenta;

        // Palette — ground, then surface a visible step off it, then slot between surface and content.
        public static readonly Color Ground      = Hex("FAF8EF"); // behind everything
        public static readonly Color Surface     = Hex("BBADA0"); // a container
        public static readonly Color SlotFill    = Hex("CDC1B4"); // an EMPTY slot in that container
        public static readonly Color TextOnLight = Hex("776E65");
        public static readonly Color TextOnFill  = Hex("F9F6F2");

        // Spacing — one atom; every spacing number in the SKU is defined here as an expression over it.
        public const float Unit     = 20f;
        public const float SlotSize = Unit * 12f;  // 240 — what the gap percentages below are relative to
        public const float Gap      = Unit * 1.5f; // 30 ≈ 12.5% of SlotSize
        public const float Pad      = Gap;

        // Type — world units, like everything else on this rig (1 font point == 1 unit). Derived over
        // Unit for the same reason spacing is: an absurd size shows up as an absurd multiplier.
        // Read "Type" below and MEASURE before you copy these numbers into a SKU.
        public const float FontLabel = Unit * 2.5f;      //  50 — a caption
        public const float FontValue = FontLabel * 3f;   // 150 — the primary value (≥ 2× its label)
        public const float FontTitle = FontLabel * 2.4f; // 120 — a dialog title
    }
}
```

**Never** a `Color`, hex literal, or bare spacing number in a View outside this file. Views *index*
tokens. A controller may still choose *which* token — `Game.Presentation` references `Game.Views`, so
that compiles — but the View alone decides how it is drawn (rule 8).

## Deciding with no spec

**Palette — build it as steps, not as favourites.** Pick a **ground**, then a **surface** one visible
step off it, then a **slot** tone between surface and content. Content sits clearly above surface in
lightness. One accent hue, reserved for the primary action. Text gets exactly two tones, chosen by a
stated threshold rather than by eye: fill **relative luminance ≥ 0.5 ⇒ `TextOnLight`**, below ⇒
`TextOnFill`.

**Setting the ground is a SKU job, and it has a specific mechanism.** The rig camera's clear colour
is Master-Scene rig work — **Ask-First**, so it is not your lever. Draw the ground instead: a
full-bleed sprite sized from `IWorldViewport` (read at the use site, never cached), parented under the
scene's `WorldRoot`, `Stamp`ed onto the lowest-order render layer that draws, with the lowest
`sortingOrder` in it. Details in `pf-world-space`. A rig default reaching a player is the tell that
nobody chose a ground at all.

**Spacing — one atom, everything an expression over it.** Choose `Unit`; define every gap and pad in
the token file as an expression over it. A slot gap reads well at roughly **10–15% of the slot**;
below ~8% the grid looks cramped and merged.

> **Do not let the safe rect pick your ratios.** Solving `n·cell + (n+1)·gap ≤ 1080` for `gap` is how
> a grid ends up at 8%. Choose cell and gap for rhythm first, then fit — `IWorldViewport` and the
> scaler exist so the *view* adapts to the design, not the design to a constant (`pf-world-space`).

**Type — three sizes per surface, at most.** Label, value, title. The primary value is ≥ 2× its label,
or the pair reads as one flat string.

**`fontSize` is a world-unit measure on this rig — size it from the box, never from a remembered
number.** The ruler runs all the way through type (`pf-world-space`): a host canvas is at
`referencePixelsPerUnit 1` and `localScale 1`, and `TextMeshProUGUI.Awake()` sets `isOrthographic =
true` unconditionally, so TMP's font scale carries **no** extra multiplier —
**`1 TMP font point == 1 design px == 1 world unit`**. Measured on LiberationSans SDF: a line box is
`1.117 × fontSize` units, a digit advances `0.558 × fontSize`, a cap height is roughly `0.7 ×
fontSize`. So a value filling about half a 240-unit slot is `fontSize ≈ 170`, and a **four-digit
`fontSize` is a red flag**: at 1500 a single line box is 1675 units — 87% of the 1920-unit safe height,
which only a full-screen countdown digit could want. These ratios move with the font, so measure once
per font and store them as tokens next to the sizes they derive.

> **The one thing that breaks the 1:1 ruler — and a bigger `fontSize` is the wrong fix.** A
> **Renderer-drawn** `TextMeshPro` (3D text under `WorldRoot`, no canvas) keeps TMP's serialized
> `isOrthographic = false`, and TMP then scales the font by **0.1**
> (`TMP_Text.cs`: `orthographicMultiplier = m_isOrthographic ? 1 : 0.1f`) — a digit lands at
> `0.073 × fontSize` and the text reads 10× too small. Inflating the token to ~1500 hides the symptom
> and leaves every metric off by 10×. **Tick Orthographic Mode (`isOrthographic = true`)** on that
> component — the rig camera *is* orthographic — and the 1:1 ruler holds there too.

**Measure it, do not remember it.** Before a type token is written down, get the ratio off the rig
with one `script-execute` on the object you just built:

```csharp
// Units per font point, for THIS font, on THIS rig. Expect ≈1.117 / ≈0.558 (LiberationSans SDF).
var t = GameObject.Find("ScoreValue").GetComponent<TMPro.TMP_Text>();
t.enableAutoSizing = false; t.fontSize = 100f; t.ForceMeshUpdate();
var v = t.GetPreferredValues("0");                       // canvas units == world units here
Debug.Log($"per point: advance={v.x / 100f:0.###} lineBox={v.y / 100f:0.###}");
```

A value that must survive its longest string needs `enableAutoSizing` plus a floor derived from that
advance, not a smaller size everywhere: four digits inside a 210-unit slot fit at
`4 × 0.558 × 70 = 156` units, so the floor token is `70`.

> A label-over-value pair is **two** text objects, not one formatted string. Rule 4 still holds: the
> label is a `LocKey`, the number is a `CultureInfo.InvariantCulture` formatted value needing none.
> "Score: 0" as a single localized line is a hierarchy you cannot build.

## The finished-surface checklist

Walk all eight before calling anything done. Each is decidable — no taste required.

| # | Check | Fails when |
|---|---|---|
| 1 | **Ground** | The rig default reaches the player, or no object draws the ground. |
| 2 | **Containment** | A container that holds slots draws no empty slots — a bare panel. |
| 3 | **Rhythm** | A spacing number appears outside the token file, or is not an expression over `Unit`. |
| 4 | **Hierarchy** | >3 type sizes on one surface, a value under 2× its label, or a `fontSize` that was never measured against the box it sits in (a four-digit one on this rig is the tell). |
| 5 | **Empty state** | Zero / empty / loading renders as nothing instead of as something. |
| 6 | **Contrast** | Text tone does not follow the luminance-0.5 rule above. |
| 7 | **Edge** | Content crosses the safe rect, or clears it by less than `Pad` on any side. |
| 8 | **Affordance** | A tappable thing has no fill/radius/label; disabled does not read disabled. |

### Who settles which check

The eight are all decidable, but not all by the same tool. Giving a vision judge the ones a grep
already answers buys nothing and adds non-determinism; giving code the ones only a looker can answer
is how a surface ships broken with every assertion green.

| Check | Settled by |
|---|---|
| 1 Ground · 2 Containment · 5 Empty state · 8 Affordance | **looking** — a person, or a vision judge over the capture |
| 3 Rhythm · 6 Contrast | **code** — a grep for spacing outside the token file; the luminance rule is arithmetic |
| 4 Hierarchy · 7 Edge | **both** — count the type sizes and read the rect from the layout in code; whether text overflows its box, or content crowds the edge, is a looker's call |

When the surface's spec carries a `## Visual Contract`, settle its rows against the capture with
`docs/framework/recipes/visual-contract-judge.md` — and read that recipe first for what the judge must
not be asked (an exact scale, an exact colour, a `sortingOrder`: those are field assertions), and for
the three rules that keep the loop from running away.

**Self-review, every time — and in _play mode_.** A change that draws earns the **visual check**
(`pf-gates` §8a): enter play mode once via `editor-application-set-state`, reach the states you named
**before** entering, and capture each with `screenshot-game-view` — at **FHD in this SKU's own
orientation** (`1080×1920` portrait, `1920×1080` landscape), read off the rig's design rect rather than
hardcoded. Pass that size explicitly to `screenshot-camera`: it defaults to landscape FHD and swaps that
aspect onto the camera, so on a portrait rig it captures an aspect the game never ships. Then walk the eight against the capture, not against your intent, and write down what you saw.
Step the aspect ratios per `pf-world-space` while you are there.

**An edit-mode capture is not the same evidence.** It shows the authored scene, not the running game —
no pooled instances, no bound data, no transition mid-flight. Use it to check a static rig; use a
play-mode capture to claim a screen is finished.

**Bounded, always.** The visual check is *one session with a stated end*. Capture **named states**, not
a playthrough: never sweep hundreds of levels, a whole palette, or a solver run through play mode — see
"Never sweep in play mode" in `pf-gates`. Need confidence over a large set? Capture a **named handful**
(first, last, the spec's extremes) and report it as a sample.

> On macOS these return null while the Editor window is unfocused — and an unfocused Editor's player
> loop does not advance at all, so play mode hangs and draws nothing. That is the cause — ask the user
> to focus the Editor and retry. Never mark the checklist walked on a capture you did not get, and
> never report a blank capture as a visual check.

A feature that draws and whose spec's Verification names no visual check is itself a finding.

## When a placeholder is legitimate

Only on an **explicit human request** — "wireframe", "greybox", "flat colour is fine", "don't spend
time on art". Record that request in the spec's `Boundaries & Constraints`, or in the commit/PR note
when the work has no spec. Absent that trace, an unfinished surface is a review finding, exactly like
a missing test — an approved greybox and a lazy one are indistinguishable in a diff.

Rule 17 governs **composition, not asset production**. Flat tinted rectangles with a coherent palette
and correct rhythm **pass**. The same rectangles on a rig-default ground with no empty slots **fail**.
Nobody is asking you to draw character art.

When the surface does need a bitmap the design package lacks — an illustrated emblem, a prop, or a
plate with an object painted out — do not fake it in code. Load `pf-asset-gen` for
`Tools/pf/asset-gen.py`. Token-drawn chrome stays in an Editor generator.

## Common failures

| Symptom | Cause | Fix |
|---|---|---|
| Game ships on a dark grey nobody chose | Rig camera clear colour treated as the ground | The rig is Ask-First; draw a full-bleed ground under `WorldRoot` instead |
| A grid is one flat panel | Only the container was authored, its slots never were | Check 2 — draw the empty slots |
| Colours drift between two features | Feature two never looked for rung 2 | One token file; index it, or extend it — never redeclare |
| A `Color[]` ramp sits in a View | Palette treated as view state | Move it to the token file and index by tier |
| Text renders ~10× too big (the token is a four-digit `fontSize`) | A size copied from a doc, an example or another rig instead of measured — here `fontSize` **is** world units | Size from the box, verify with `GetPreferredValues`, store the ratio as a token |
| A Renderer-drawn TMP renders ~10× too small | `isOrthographic == false` ⇒ TMP's ×0.1 font scale | Tick Orthographic Mode on the component — never compensate with a bigger `fontSize` |
| Grid looks cramped | `gap` solved out of a safe-rect equation | Rhythm first, fit second |
